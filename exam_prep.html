Chapter 1

The Big Picture — What Are We Building?

In this course we build a full-stack e-commerce website called Licorne. "Full-stack" means we build everything: the visual interface the user sees (Frontend), the server that processes requests (Backend), and the database that stores data permanently (Database).

The Three Layers

🖥️ Frontend (Client)

What the user sees and interacts with inside their browser. Built with React. Runs on the user's computer. Sends requests to the backend when it needs data.

⚙️ Backend (Server)

A program running on a remote computer that receives requests, processes them (business logic), talks to the database, and sends responses back. Built with Node.js + Express.

🗄️ Database

Permanent data storage. Like a giant organized filing cabinet. We use MongoDB — a NoSQL database that stores data as JSON-like documents instead of tables.

What is "MERN"?

MERN is an acronym for the four core technologies used together:

LetterTechnologyRole
MMongoDBDatabase — stores products, users, orders
EExpressBackend framework — creates the API server
RReactFrontend library — builds the user interface
NNode.jsRuntime — lets JavaScript run outside the browser
🧠 Exam Logic: If asked "What is the MERN stack?", answer: it's a combination of four technologies (MongoDB, Express, React, Node.js) that together allow building a complete web application using only JavaScript across all layers.

Key Vocabulary

API (Application Programming Interface)

A set of URLs (called endpoints) that the backend exposes so the frontend can ask for data. Example: GET /api/products returns all products as JSON. The frontend never talks to the database directly — it always goes through the API.

JSON (JavaScript Object Notation)

A lightweight text format for representing structured data. It looks like a JavaScript object: { "name": "Phone", "price": 599 }. This is the language the frontend and backend speak when exchanging data.

HTTP Methods

GET = retrieve data. POST = send/create data. PUT = update data. DELETE = remove data. In our project we mainly use GET (fetching products).

Port

A number that identifies which program should receive network traffic on a computer. Our frontend runs on port 3000 and our backend on port 5000. Think of it like apartment numbers in a building — same building (computer), different doors.

SPA — Single Page Application

A website that loads one single HTML page and then dynamically updates content using JavaScript, without ever reloading the entire page. React builds SPAs. The browser doesn't request new HTML pages from the server — React replaces parts of the page internally.

Chapter 3

Terminal Commands, npm, and npx

What is the Terminal?

The terminal is a text-based interface where you type commands to control your computer — create files, install packages, run servers, etc. In VS Code, you open it with Ctrl + ` (backtick).

What is npm?

npm (Node Package Manager) is a tool that comes bundled with Node.js. It lets you:

  • Download and install packages (pre-made code libraries written by other developers)
  • Manage your project's dependencies (the list of packages your project needs)
  • Run custom scripts defined in package.json

npm vs npx — The Difference

npm install (or npm i)

Downloads a package and saves it permanently in your project's node_modules folder. The package name gets recorded in package.json so anyone can reinstall it later.

npx

Downloads and runs a package once without permanently installing it. Perfect for setup tools you only need once, like create-react-app.

Essential npm Commands

CommandWhat It DoesWhen You Use It
npm initCreates a package.json file with project infoOnce, when starting a new Node.js project
npm i <package>Installs a package as a dependencynpm i express installs Express
npm i -D <pkg>Installs as a dev dependency (only needed during development, not in production)npm i -D nodemon
npm startRuns the "start" script from package.jsonLaunch the server or app
npm run <name>Runs any custom script by namenpm run dev, npm run server
npx create-react-app frontendCreates a complete React project scaffold in a folder called "frontend"Once, at the beginning of a React project

The package.json File

Every Node.js project has a package.json. It's a JSON file that stores:

  • Project metadata — name, version, description
  • Scripts — custom commands you can run with npm run
  • Dependencies — packages your project needs to run
  • Dev Dependencies — packages only needed during development
// Example package.json (root of our project)
{
  "name": "example",
  "type": "module",            // ← enables import/export syntax (ES modules)
  "scripts": {
    "start":        "node backend/server.js",       // npm start → launches backend
    "server":       "nodemon backend/server.js",    // npm run server → auto-restarts on changes
    "client":       "npm start --prefix frontend",  // npm run client → starts React
    "dev":          "concurrently \"npm run server\" \"npm run client\"", // runs BOTH!
    "data:import":  "node backend/seeder.js",       // seeds the database
    "data:destroy": "node backend/seeder.js -d"     // clears the database
  },
  "dependencies": { "express": "^5.2.1", "mongoose": "^9.4.1", ... },
  "devDependencies": { "nodemon": "^3.1.14", "concurrently": "^9.2.1", ... }
}

"type": "module" — this line is critical. Without it, Node.js uses the old require() syntax. With it, we can use modern import/export.

concurrently lets you run multiple commands simultaneously. The dev script runs both backend AND frontend servers with one command.

🧠 Exam Logic: Know the difference between dependencies and devDependencies. Dependencies are needed for the app to run (express, mongoose). Dev dependencies are only needed during development (nodemon, concurrently) — they're not shipped to production.

nodemon — Why We Use It

Normally, when you change a file in your backend, you have to stop the server and restart it to see changes. nodemon watches your files and automatically restarts the server whenever you save a change. That's why we use npm run server (which uses nodemon) during development instead of npm start (which uses plain node).

Chapter 5

React — Core Concepts

What is React?

React is a JavaScript library created by Facebook (Meta) for building user interfaces. Instead of the browser reloading the entire page when something changes, React only updates the parts that actually changed.

How to Create a New React Project

npx create-react-app frontend     # Creates a React project in a folder called "frontend"
cd frontend                        # Move into that folder
npm start                          # Start the development server at localhost:3000

This generates all the starter files you need. After running npm start, your browser opens automatically to http://localhost:3000.

What is the Virtual DOM?

The browser has a DOM (Document Object Model) — a tree structure representing every element on the page. Changing the real DOM directly is slow. React maintains a lightweight copy called the Virtual DOM. When data changes:

State changes
→
React builds new Virtual DOM
→
Compares with old (diffing)
→
Updates only changed parts
🧠 Exam Logic: The Virtual DOM is React's performance optimization. It doesn't re-render the entire page — it calculates the minimal set of changes and applies only those to the real browser DOM.

What is JSX?

JSX = JavaScript + XML. It's a syntax extension that lets you write HTML-like code directly inside JavaScript. It is not actual HTML — it gets compiled into JavaScript function calls.

// JSX — what you write:
const element = <h1>Hello, {name}</h1>

// What React transforms it into (you never write this):
const element = React.createElement('h1', null, 'Hello, ', name)

JSX uses className instead of class (because "class" is a reserved word in JS).

Self-closing tags must end with />: <img src={logo} />

Use curly braces { } to embed any JavaScript expression inside JSX.

What is a Component?

A component is a JavaScript function that returns JSX. It represents a reusable piece of the user interface — a button, a card, a whole page, or even the entire app.

Rules:
1. Component names must start with a capital letter — React uses this to distinguish components (<Header />) from HTML tags (<div>).
2. A component must return a single root element. To return multiple siblings, wrap them in a Fragment: <>...</>.

Props vs State — The Two Types of Data

Props (Properties)

Data passed from parent to child. Like function arguments. The child cannot modify them. Data flows one-way: downward only (parent → child).

State

Data that lives inside a component and can change. When state changes, React automatically re-renders the component. Managed with the useState hook.

📝 Exam Tip: A common exam question: "What is the difference between props and state?"
Props = external, read-only, passed by parent. State = internal, mutable, managed by the component itself. Both can trigger re-renders, but only state can be modified by the component that owns it.

Chapter 7

Components — How They Work

Creating a Component — the Pattern

Every React component follows the same structure:

// 1. IMPORTS — bring in what you need
import { Card } from 'react-bootstrap'

// 2. COMPONENT FUNCTION — receives props, returns JSX
const Product = ({ product }) => {    // destructures the 'product' prop
  return (
    <Card>
      <Card.Body>
        <strong>{product.name}</strong>
        <p>${product.price}</p>
      </Card.Body>
    </Card>
  )
}

// 3. EXPORT — make it available for other files to import
export default Product

The { product } syntax is object destructuring. It extracts the product key from the props object passed by the parent.

export default means this component is the main export of this file. When importing, you don't need curly braces: import Product from './Product'

How a Parent Passes Props to a Child

// In HomeScreen.js (parent):
{products.map((product) => (
  <Product key={product._id} product={product} />
  //        ↑ unique key       ↑ passing data as a prop named "product"
))}

// In Product.js (child) — receives it:
const Product = ({ product }) => { ... }
🧠 Exam Logic — The "key" prop: When rendering a list with .map(), React requires a unique key prop on each item. This is how React's Virtual DOM tracks individual items to efficiently update only what changed. We use product._id (the MongoDB ID) as the key.

How the Rating Component Works (Logic)

The Rating component receives a numeric value (like 4.5) and displays 5 star positions. For each position, it decides:

ConditionIcon ShownExample for Star 3 (position 3)
value ≥ position★ Full starvalue is 3, 3.5, 4, etc. → full
value ≥ position - 0.5⯨ Half starvalue is 2.5 → half
otherwise☆ Empty starvalue is 2 or less → empty

This creates a cascading visual: a rating of 3.5 shows ★★★⯨☆.

Chapter 8

React Hooks — useState and useEffect

Hooks are special functions that let React components access features like state management and side effects. They always start with use and must be called at the top level of a component (never inside loops, conditions, or nested functions).

useState — Managing Data That Changes

import { useState } from 'react'

const [products, setProducts] = useState([])
//     ↑ current value  ↑ function to update it  ↑ initial value (empty array)

useState returns an array with exactly 2 items: [currentValue, setterFunction]. We use array destructuring to name them.

When you call setProducts(newData), React re-renders the component with the new value. You should never modify state directly (no products = ...).

useEffect — Running Code After Render

useEffect runs side effects — code that should happen after the component renders. The most common use: fetching data from an API.

import { useEffect } from 'react'

useEffect(() => {
  // This code runs after the component renders
  const fetchProducts = async () => {
    const { data } = await axios.get('/api/products')
    setProducts(data)
  }
  fetchProducts()
}, [])    // ← dependency array

Empty array [] = run the effect only once when the component first appears on screen (mount). This is how we fetch data on page load.

Array with value [productId] = run once on mount, then again every time productId changes. Used in ProductScreen to reload when the URL changes.

No array at all = run on every single render. This is almost always a bug — avoid it.

📝 Exam Logic — The Three Dependency Array Cases:
useEffect(() => {...}) → runs every render (usually wrong)
useEffect(() => {...}, []) → runs ONCE on mount (data fetch on page load)
useEffect(() => {...}, [id]) → runs on mount + whenever id changes

If asked "why does the useEffect have []?", answer: to prevent infinite loops. Without it, the effect runs → updates state → triggers re-render → effect runs again → infinite loop.

useParams — Reading URL Parameters

From React Router DOM. Extracts dynamic parts from the URL:

// If the URL is /product/abc123 and the route is /product/:id
const { id: productId } = useParams()
// productId = 'abc123'
// The "id" comes from :id in the Route definition
// ": productId" renames it to a more descriptive variable name
Chapter 9

React Router DOM — Client-Side Navigation

What Problem Does It Solve?

Without React Router, clicking a link causes the browser to request a completely new HTML page from the server, reloading everything. With React Router, navigation happens entirely in JavaScript — the page never reloads, content just swaps instantly. This is what makes React a Single Page Application.

How We Set It Up (in index.js)

import { createBrowserRouter, createRoutesFromElements, Route, RouterProvider }
  from 'react-router-dom'

const router = createBrowserRouter(
  createRoutesFromElements(
    <Route path="/" element={<App />}>                 // Parent: App wraps all
      <Route index={true} path="/" element={<HomeScreen />} />  // Child: shows at /
      <Route path="/product/:id" element={<ProductScreen />} /> // Child: shows at /product/123
    </Route>
  )
)

root.render(
  <RouterProvider router={router} />  // Replaces direct <App />
)
🧠 Key Concepts:
• <Route path="/product/:id"> — the :id is a dynamic parameter. It matches any value: /product/1, /product/abc, etc.
• index={true} — this route is the default child route (shown when the parent path matches exactly).
• <Outlet /> in App.js — this is where the matched child route gets rendered.
• <Link to="/..."> replaces <a href="..."> — it navigates without page reload.
• <LinkContainer to="/..."> from react-router-bootstrap — wraps Bootstrap <Nav.Link> to make it work with React Router.

href vs Link — Why It Matters

❌ <a href="/product/1">

Triggers a full page reload. The browser sends a new HTTP request to the server and re-downloads everything. Slow. Loses component state.

✅ <Link to="/product/1">

React Router intercepts the click, updates the URL, and swaps the component in the Outlet. No reload. Instant. State preserved.

Chapter 10

Backend — Express Server

What is Express?

Express is a minimal web framework for Node.js. It lets you create a server that listens for HTTP requests and sends back responses. Think of it as: "when someone visits URL X, do action Y and return data Z."

Setting Up the Backend (Step by Step)

  1. At the project root, run npm init — creates package.json. Set entry point to server.js.
  2. Add "type": "module" to package.json — enables modern import/export syntax.
  3. Create backend/ folder and backend/server.js file.
  4. Install Express: npm i express
  5. Write the server code (see below).
  6. Add start script: "start": "node backend/server.js"
  7. Run: npm start → server starts on port 5000.

server.js — How It Works

backend/server.js 
import express from 'express'
import dotenv from 'dotenv'
import connectDB from './config/db.js'
import products from './data/products.js'

const port = process.env.PORT || 5000   // Read port from .env, fallback to 5000

connectDB()                             // Connect to MongoDB
const app = express()                    // Create Express app instance

// Route 1: Root endpoint — just confirms the API is running
app.get('/', (req, res) => {
  res.send('API is running ...')
})

// Route 2: Get ALL products
app.get('/api/products', (req, res) => {
  res.json(products)                   // Send products array as JSON
})

// Route 3: Get ONE product by ID (dynamic parameter)
app.get('/api/products/:id', (req, res) => {
  const product = products.find((p) => p._id === req.params.id)
  res.json(product)                   // Send matching product as JSON
})

app.listen(port, () => console.log(`Server running on port ${port}`))
🧠 Exam Logic — Express Routing:
• app.get(path, handler) defines a route. When someone sends a GET request to that path, the handler function runs.
• req = the request object (contains info about what the client asked for).
• res = the response object (used to send data back).
• req.params.id reads the :id from the URL. If someone visits /api/products/5, then req.params.id is "5".
• res.json() converts JavaScript data to JSON and sends it to the client.
• res.send() sends plain text.

Environment Variables (.env)

Sensitive configuration (passwords, API keys, port numbers) goes in a .env file at the project root. The dotenv package loads these values into process.env.

NODE_ENV=development
PORT=5000
MONGO_URI=mongodb+srv://user:password@cluster0.mongodb.net/licorne
Never commit .env to Git! It contains passwords. Add it to .gitignore. Share a template file (example.env) with placeholder values so others know what variables are needed.
Chapter 11

Full-Stack Communication — Connecting Front and Back

The Problem: CORS

The frontend runs on localhost:3000 and the backend on localhost:5000. Browsers block requests between different origins (ports count!) for security. This is called CORS (Cross-Origin Resource Sharing).

The Solution: Proxy

In the frontend's package.json, we add:

"proxy": "http://localhost:5000"

This tells the React development server: "whenever a request comes in that you can't handle (like /api/products), forward it to port 5000." Now we can write axios.get('/api/products') in the frontend without specifying the full URL.

📝 Exam Tip: If asked "How do we make the frontend communicate with the backend?", the answer involves: (1) installing axios in the frontend, (2) adding a proxy in frontend's package.json pointing to the backend port, and (3) using useState + useEffect to fetch data and update the UI.

Axios — The HTTP Client

Axios is a library for making HTTP requests from JavaScript. We install it in the frontend: npm i axios

const { data } = await axios.get('/api/products')
// axios.get() returns a response object
// { data } destructures the 'data' key from that response
// 'data' contains the actual JSON the server sent back

The Complete Data Flow — HomeScreen

  1. User opens the website → React renders HomeScreen
  2. useEffect fires (empty [] dependency = runs once on mount)
  3. Inside it, axios.get('/api/products') sends a GET request
  4. The proxy forwards the request to localhost:5000/api/products
  5. Express matches the route, calls res.json(products)
  6. Axios receives the JSON response
  7. setProducts(data) updates the state
  8. React re-renders HomeScreen, calling products.map() to create Product cards

The Complete Data Flow — ProductScreen

  1. User clicks a product card → React Router changes URL to /product/abc123
  2. Router renders ProductScreen inside the <Outlet />
  3. useParams() extracts id = "abc123" from the URL
  4. useEffect fires with [productId] dependency
  5. axios.get(`/api/products/${productId}`) sends request with dynamic ID
  6. Express matches /api/products/:id, finds the product, returns it
  7. setProduct(data) updates state → screen shows product details
Why [productId] in the dependency array? If the user navigates from product A to product B (the URL changes but the same component is used), the useEffect needs to re-run to fetch the new product's data. The dependency array tells React: "re-run this effect whenever productId changes."

MongoDB — The Database

What is MongoDB?

MongoDB is a NoSQL database. Unlike traditional SQL databases that store data in tables with rows and columns, MongoDB stores data as documents — objects that look like JSON. Multiple documents are grouped into collections.

SQL (Traditional)

Tables → Rows → Columns
Fixed schema (every row must have same columns)
Uses SQL language for queries

NoSQL (MongoDB)

Collections → Documents → Fields
Flexible schema (documents can have different fields)
Uses JavaScript-like syntax for queries

MongoDB Atlas — Cloud Database Setup

  1. Create an account on mongodb.com
  2. Create a new Project (we called it "Licorne")
  3. Click "Build a Database" → choose the free tier → select AWS provider
  4. Create a database user (username + password) — this is different from your MongoDB account
  5. Set IP access — either your specific IP or 0.0.0.0/0 (allow from anywhere)
  6. Click "Connect" → "Connect your application" → copy the connection string
  7. Paste it in your .env file as MONGO_URI, replacing the password and database name

MongoDB Compass — Desktop GUI

MongoDB Compass is a desktop application that lets you visually browse your database. You can connect to:

  • Local database: mongodb://localhost:27017
  • Cloud database (Atlas): paste the connection string from Atlas

Chapter 13

Mongoose — Schemas, Models, and Database Seeding

What is Mongoose?

Mongoose is an ODM (Object Data Modeling) library for MongoDB. It sits between your Node.js code and MongoDB, providing:

  • Schemas — define the shape/structure of documents (what fields, what types, what constraints)
  • Models — compiled from schemas, they provide methods to create, read, update, and delete documents
  • Validation — ensures data matches the expected format before saving

Schema vs Model — The Difference

Schema (The Blueprint)

Defines the structure: which fields exist, their types (String, Number, Boolean), whether they're required, default values. Like a blueprint for a house.

Model (The Constructor)

Created from a schema. Provides the actual methods to interact with the database: find(), findById(), insertMany(), deleteMany(). Like the construction company that builds from the blueprint.

Connecting to MongoDB (db.js)

backend/config/db.js 
import mongoose from 'mongoose'

const connectDB = async () => {
  try {
    const conn = await mongoose.connect(process.env.MONGO_URI)
    console.log(`MongoDB Connected: ${conn.connection.host}`)
  } catch (error) {
    console.error(`Error: ${error.message}`)
    process.exit(1)    // Exit with failure code — app cannot run without DB
  }
}

export default connectDB
🧠 Logic: process.exit(1) means "crash the application with an error." Code 1 = failure. Code 0 = success. If the database can't connect, there's no point in running the server.

Product Schema Example

backend/models/productModel.js 
import mongoose from 'mongoose'

// Sub-schema for reviews (embedded inside products)
const reviewSchema = mongoose.Schema({
  user:    { type: mongoose.Schema.Types.ObjectId, required: true, ref: 'User' },
  name:    { type: String, required: true },
  rating:  { type: Number, required: true },
  comment: { type: String, required: true },
}, { timestamps: true })

// Main product schema
const productSchema = new mongoose.Schema({
  user:         { type: mongoose.Schema.Types.ObjectId, required: true, ref: 'User' },
  name:         { type: String,  required: true },
  image:        { type: String,  required: true },
  brand:        { type: String,  required: true },
  category:     { type: String,  required: true },
  description:  { type: String,  required: true },
  reviews:      [reviewSchema],      // Embedded sub-documents
  rating:       { type: Number, required: true, default: 0 },
  numReviews:   { type: Number, required: true, default: 0 },
  price:        { type: Number, required: true, default: 0 },
  countInStock: { type: Number, required: true, default: 0 },
}, { timestamps: true })

const Product = mongoose.model('Product', productSchema)
export default Product
🧠 Exam Logic — Schema Concepts:
• type: String / Number / Boolean — defines what data type the field accepts
• required: true — this field is mandatory; saving without it causes an error
• default: 0 — if no value is provided, use 0
• ref: 'User' — creates a reference (relationship) to another collection. This field stores a User's _id
• mongoose.Schema.Types.ObjectId — the field stores a MongoDB ObjectId (unique identifier)
• [reviewSchema] — an array of sub-documents. Each product contains its own list of review objects
• timestamps: true — automatically adds createdAt and updatedAt fields to every document
• mongoose.model('Product', productSchema) — compiles the schema into a usable Model

Seeder Script — Populating the Database

The seeder.js file is a utility script that fills the database with test data (or clears it). It is not part of the app — you run it separately.

// seeder.js — simplified logic:

// IMPORT mode (npm run data:import):
await Order.deleteMany()          // 1. Clear all existing data
await Product.deleteMany()
await User.deleteMany()
const createdUsers = await User.insertMany(users)  // 2. Insert mock users
const adminUser = createdUsers[0]._id               // 3. Get admin's ID
const sampleProducts = products.map(p => ({
  ...p, user: adminUser                             // 4. Add admin as owner
}))
await Product.insertMany(sampleProducts)              // 5. Insert products

// DESTROY mode (npm run data:destroy):
if (process.argv[2] === '-d') {
  await Order.deleteMany()
  await Product.deleteMany()
  await User.deleteMany()
}

process.argv[2] checks the terminal argument. node seeder.js -d → argv[2] is "-d" → destroy mode.

The spread operator ...p copies all existing product fields, then adds/overwrites the user field with the admin's ID.

bcryptjs — Why Hash Passwords?

In users.js (mock data), passwords are hashed using bcryptjs. Hashing converts a password into an unreadable string. Even if someone steals the database, they can't read the original passwords.

import bcrypt from 'bcryptjs'

const users = [
  { name: 'Admin', email: 'admin@email.com',
    password: bcrypt.hashSync('123456', 10),  // hashes "123456"
    isAdmin: true }
]
📝 Exam Tip: If asked "Why do we use bcryptjs?", answer: to hash passwords before storing them in the database. Hashing is a one-way function — you can't reverse it to get the original password. This protects users even if the database is compromised.

Logic Cheatsheet — "Why" Questions for the Exam

Your professor said the exam is about logic. Here are the most likely "why" and "what" questions, with clear answers:

🔹 Why do we use "type": "module" in package.json?

To enable ES6 import/export syntax in Node.js. Without it, Node uses the older require() syntax. We need it because React uses import/export, and we want consistency across frontend and backend.

🔹 Why does create-react-app put everything in one HTML file?

Because React builds a Single Page Application. One HTML file with one <div id="root">. React fills this div dynamically with JavaScript. Navigating between "pages" doesn't load new HTML — React just swaps components.

🔹 What is the role of index.js in React?

It's the entry point. It finds the <div id="root"> from index.html, creates a React root, sets up the Router, and renders the App component into it.

🔹 What is the role of App.js?

It's the layout shell. It contains elements that appear on every page (Header, Footer) and uses <Outlet /> as a placeholder where the routed screen components are dynamically injected.

🔹 Why use useEffect with an empty dependency array?

To run code only once when the component mounts. Perfect for initial API calls. Without the empty array, the effect runs on every render → state updates → re-render → effect runs again → infinite loop.

🔹 Why do we need a proxy in frontend/package.json?

To avoid CORS errors. The frontend (port 3000) and backend (port 5000) are different origins. The proxy tells the dev server to forward API requests to port 5000, making the browser think they're from the same origin.

🔹 What is the difference between a Mongoose Schema and a Model?

Schema defines the structure (fields, types, validations). Model is compiled from the schema and provides database methods (find, create, update, delete). Schema is the blueprint; Model is the builder.

🔹 Why do we use req.params.id in Express?

To read dynamic URL parameters. When the route is /api/products/:id, the :id part captures whatever value is in the URL. req.params.id lets us access that value in the handler.

🔹 Why do we need a "key" prop when using .map() in React?

React uses keys to identify which items changed in the Virtual DOM. Without unique keys, React has to re-render the entire list. With keys, it only updates the items that actually changed — this is a performance optimization.

🔹 What is the role of the seeder script?

It populates the database with test data (import mode) or clears all data (destroy mode with -d flag). It deletes existing data first to prevent duplicates, then inserts users and products from mock data files.

🔹 What does npm run dev do in our project?

It runs the dev script from package.json, which uses concurrently to start both the backend server (with nodemon, for auto-restart) and the frontend React server at the same time.

🔹 Why do we use nodemon instead of node?

Nodemon watches for file changes and automatically restarts the server. With plain node, you'd have to manually stop and restart every time you change a file.

🔹 What is the role of the .env file?

Stores sensitive configuration (database passwords, port numbers, API keys) outside the code. It's listed in .gitignore so it never gets uploaded to GitHub.

🔹 What does timestamps: true do in a Mongoose schema?

Automatically adds two fields to every document: createdAt (when created) and updatedAt (when last modified). Mongoose manages these automatically.

🔹 What is the role of <Outlet /> in App.js?

It's a placeholder component from React Router. It marks where the matched child route component should be rendered. When the URL is /, HomeScreen renders inside the Outlet. When the URL is /product/:id, ProductScreen renders there instead.

🔹 What is the difference between <Link> and <a href>?

<a href> causes a full page reload. <Link to> uses React Router to update the URL and swap components without reloading the page. Always use Link in React apps for internal navigation.

🔹 What does ref: 'User' mean in a Mongoose schema?

It creates a reference (relationship) between two collections. The field stores a User's ObjectId, linking a product to the user who created it. Similar to a foreign key in SQL.

🔹 Why hash passwords with bcryptjs?

To protect user data. Hashing converts passwords into unreadable strings. Even if someone accesses the database, they can't recover the original passwords. Hashing is one-way — you can check if a password matches a hash, but you can't reverse the hash.
